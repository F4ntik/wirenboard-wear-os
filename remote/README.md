# HTTPS-доступ к свету

Шлюз `gateway.py` принимает запросы на `127.0.0.1:8765` и связывается с существующими каналами освещения по MQTT. Для доступа вне дома его можно добавить в «Сервисы» Wiren Board Cloud. Белый IP и открытие портов на роутере не требуются. Также поддерживается собственный HTTPS-адрес с туннелем на этот локальный порт. [Сервисы Wiren Board Cloud](https://wiki.wirenboard.com/wiki/Wiren_Board_Cloud#controller-services)

## Пакет для контроллера Wiren Board

В [выпуске 0.5.1](https://github.com/F4ntik/wirenboard-wear-os/releases/tag/v0.5.1) лежат готовый пакет `wb-wear-light-gateway_0.1.0_all.deb` для учебной карты и архив `wirenboard-wear-os-0.5.1-windows.zip` с APK и программой привязки. Если проверяете саму интеграцию на стенде с учебной картой, можно сразу перейти к установке пакета. Для домашней схемы укажите свои каналы в `gateway.py`, согласуйте их с приложением часов и соберите пакет на Debian 11 или новее.

```sh
sudo apt install build-essential debhelper dpkg-dev
cd remote
chmod 0644 debian/*
chmod 0755 debian/rules debian/postinst debian/postrm
dpkg-buildpackage -b -us -uc
cd ..
```

Скопируйте `wb-wear-light-gateway_0.1.0_all.deb` на контроллер и установите его в терминале.

```sh
sudo apt install ./wb-wear-light-gateway_0.1.0_all.deb
```

После установки шлюз выключен. Обновите страницу Wiren Board, откройте **Интеграции → Пульт света Wear OS**, отметьте **Включить шлюз** и нажмите **Записать**. На версиях HomeUI без этого раздела откройте **Настройки → Конфигурационные файлы → Шлюз освещения Wear OS**. Сохранение применяет настройку сразу, а контроллер учитывает её после перезагрузки. Шлюз слушает только на самом контроллере и подключается к его брокеру на `127.0.0.1:1883`. [Редактор Wiren Board](https://wiki.wirenboard.com/wiki/Usage-Guide-JSON-Editor) · [Меню HomeUI](https://github.com/wirenboard/homeui#custom-menu)

После настройки внешнего HTTPS-адреса можно открыть окно привязки через терминал контроллера. Если служба включена, выполните команды от имени администратора.

```sh
sudo systemctl kill --kill-who=main --signal=SIGUSR1 wb-wear-light-gateway
sudo cat /run/wb-wear-light-gateway/pair-code
```

Для WB Cloud введите восьмизначный код в установщике на компьютере. При использовании собственного HTTPS-адреса код вводится в разделе «Доступ из интернета» на часах. Он действует пять минут и погашается после первого использования. Ключ хранится с правами `0600` в `/var/lib/wb-wear-light-gateway/token.env`. Чтобы отозвать доступ потерянных часов, остановите службу, удалите этот файл и выполните `sudo dpkg-reconfigure wb-wear-light-gateway`. Пакет создаст новый ключ. Если шлюз включён в настройках, запустите службу командой `sudo systemctl start wb-wear-light-gateway` и привяжите часы повторно.

## Привязка через Wiren Board Cloud

1. Включите шлюз в веб-интерфейсе контроллера. В личном кабинете WB Cloud откройте этот контроллер → **Сервисы** и добавьте порт `8765`. Имя в списке можно выбрать своё.
2. Распакуйте архив для Windows. Для своей карты замените в нём `app-debug.apk` собственным собранным APK. Подключите часы к компьютеру через Android Debug Bridge (ADB) и запустите `install_wb_cloud.cmd`. Вам понадобятся Python 3 и Android Platform Tools. Один раз войдите в WB Cloud на компьютере. Выберите аккаунт, которому можно доверить доступ с этих часов. Код двухфакторной защиты нужен, если она включена.
3. Программа подключится к опубликованному сервису и привяжет пульт по одноразовому коду шлюза. Когда сами часы прочитают состояние света, установщик это подтвердит. Открывать сайт на часах не требуется.

По умолчанию установщик обращается к приложению `com.galaxywatch.home.sample`. Если в своей копии изменили `applicationId`, укажите его также в `PACKAGE` в [install_wb_cloud.py](../tools/install_wb_cloud.py).

Если часы будут доступны позже, откройте [форму предварительной привязки](../tools/prepare_wb_cloud.cmd). Для запуска той же формы из терминала Windows выполните команду.

```powershell
python tools/install_wb_cloud.py --prepare
```

Установщик сначала прочитает состояние через облако и сохранит профиль в зашифрованном хранилище текущего пользователя Windows. Пароль в файл не записывается. Когда часы будут рядом, запустите `tools/install_wb_cloud.cmd` из той же учётной записи на этом ПК. Скрипт найдёт подготовленный профиль и удалит его с компьютера после того, как часы подтвердят чтение. Если часы уже сопрягались по ADB, но не подключились автоматически, укажите IP и порт с основного экрана «Беспроводная отладка». Для первого сопряжения используйте `adb pair` с данными, которые показывают часы. [Беспроводное подключение ADB](https://developer.android.com/tools/adb#wireless-android11-command-line)

При наличии уже открытого администратором сеанса PuTTY к контроллеру параметр `--pair-with-putty IP_КОНТРОЛЛЕРА` позволяет получить краткоживущий код автоматически. Привязка через ADB рассчитана на входящий в проект отладочный APK. Для отзыва доступа облачную сессию можно завершить в настройках безопасности WB Cloud.

Выключатель в интеграциях WB останавливает шлюз и закрывает порт. Локальный режим часов подключается по домашнему Wi-Fi непосредственно к MQTT.

## Локальный запуск

1. Установите Python 3.9 или новее и зависимости командой `python -m pip install -r remote/requirements.txt`.
2. Создайте случайный токен командой `python -c "import secrets; print(secrets.token_urlsafe(32))"`. Сохраните его в менеджере паролей и передайте шлюзу в переменной окружения `WB_GATEWAY_TOKEN`.
3. Если шлюз запущен отдельно от Wiren Board, задайте локальный адрес брокера в `WB_MQTT_HOST`. Порт по умолчанию `1883`, его можно изменить в `WB_MQTT_PORT`. Для брокера с паролем задайте `WB_MQTT_USERNAME` и `WB_MQTT_PASSWORD`. Права подписки и публикации можно ограничить перечисленными в `gateway.py` каналами состояния и команд. [Настройка доступа к MQTT в Wiren Board](https://wiki.wirenboard.com/wiki/MQTT)
4. Запустите `python remote/gateway.py`. Порт шлюза можно выбрать аргументом `--port`.
5. Получите состояние через локальный запрос PowerShell.

   ```powershell
   Invoke-RestMethod http://127.0.0.1:8765/v1/state -Headers @{ Authorization = "Bearer $env:WB_GATEWAY_TOKEN" }
   ```

Для внешнего адреса используйте действительный TLS-сертификат. Направляйте туннель только в этот шлюз. Используйте MQTT через loopback или в доверенной домашней сети.

## Подключение часов

1. Запустите шлюз с `--pair-once` в доверенном терминале, сохранив настроенный `WB_GATEWAY_TOKEN`. Если шлюз уже слушает этот порт, сначала остановите его.
2. В меню «Подключение» на часах введите внешний `https://` адрес и напечатанный в терминале восьмизначный код, включая ведущие нули. Код действует пять минут. После использования или восьми неверных попыток выдача закрывается до нового запуска с `--pair-once`.
3. После подключения шлюз продолжает обслуживать часы. При обычном запуске выпуск нового кода выключен. При потере часов замените токен в окружении шлюза, перезапустите его с `--pair-once` и повторите привязку.

`POST /v1/pair` принимает `{"code":"01234567"}` без заголовка `Authorization` и один раз возвращает токен. `400` означает неверный формат, `403` — неверный код, `429` — лимит ошибок, `410` — выдача недоступна. Остальные запросы требуют `Authorization: Bearer …`.

## Запросы приложения

- `GET /v1/state` возвращает состояние «Отпуска» и всех 12 каналов. Значение `null` означает, что состояние ещё неизвестно.
- `POST /v1/lights` принимает `{"lights":{"101/K1":false}}` либо `{"allOff":true}`. Отдельная команда для `102/K4` запрещена. В общее выключение входят все 12 каналов.
- Успешная команда возвращает такой же снимок, как `GET`. Шлюз ждёт свежие значения изменяемых линий, затем сверяет все целевые состояния. Общее выключение отправляет существующую команду `AllOff` один раз. Если все 12 линий уже выключены, снимок показывает состояние света, а отправка MQTT подтверждает запись команды в сокет.
- `401` означает неверный токен, `403` — включённый или неизвестный «Отпуск», `409` — уже выполняется команда. `503` означает, что брокер недоступен. При `504` приложение не получило подтверждения, часть линий могла успеть изменить состояние. Шлюз не повторяет команды.

Проверка с подставным MQTT-брокером и локальными HTTP-запросами запускается так.

```powershell
python -B -m unittest discover -s remote -v
```
