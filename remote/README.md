# HTTPS-доступ к свету

Шлюз `gateway.py` принимает запросы на `127.0.0.1:8765` и связывается с существующими каналами освещения по MQTT. Для доступа вне дома его можно добавить в «Сервисы» Wiren Board Cloud. Белый IP и открытие портов на роутере не требуются. Также поддерживается собственный HTTPS-адрес с туннелем на этот локальный порт. [Сервисы Wiren Board Cloud](https://wiki.wirenboard.com/wiki/Wiren_Board_Cloud#controller-services)

## Пакет для контроллера Wiren Board

Скачайте [пакет для Wiren Board (.deb)](https://github.com/F4ntik/wirenboard-wear-os/releases/download/v0.8.1/wb-wear-light-gateway_0.2.0_all.deb) и скопируйте файл на контроллер, например через файловый менеджер WB Cloud. В терминале **контроллера** перейдите в папку с файлом и выполните команду от имени администратора. Если вы вошли как `root`, можно опустить `sudo`.

```sh
sudo apt install ./wb-wear-light-gateway_0.2.0_all.deb
```

После новой установки шлюз выключен, список комнат пуст. Откройте **Интеграции → Пульт света Wear OS**. На версиях HomeUI без этого раздела путь начинается с **Настройки → Конфигурационные файлы**.

1. В разделе **Комнаты** добавьте комнату. В поле **На часах** введите её название.
2. Добавьте лампу, введите её название в поле **На часах** и выберите **Выключатель** из списка каналов контроллера.
3. Отметьте **Включить пульт** и нажмите **Записать**. Редактор сохраняет настройки и перезапускает службу. Часы получат новую схему по домашней сети или через уже настроенный HTTPS-доступ.

Чтобы подобрать рисунок комнаты, раскройте **Оформление комнаты**. В настройках лампы раскройте **Оформление, яркость и цвет**. Для диммера можно выбрать канал с диапазоном `0…100`, для цветной лампы — канал RGB. При обычной настройке оставьте оба поля **Для всего дома** пустыми. Общее выключение уже работает для ламп из списка.

Если есть сценарий «Я ухожу», в поле **Погасить весь дом** можно выбрать его кнопку (`pushbutton`). Поле **Режим «Отпуск»** принимает отдельный переключатель (`switch`): пока он включён, команды с часов заблокированы. Как сделать свою кнопку и переключатель, выбрать существующие каналы и проверить результат, показано на примере виртуальной лампы. [Настроить общую кнопку и блокировку](../docs/house-scenarios.md)

Редактор сохраняет привязку избранного при переименовании и настройке сохранённых комнат и ламп.

При обновлении с `0.1.0` сохраняются старый файл, ключ и API `/v1` для часов со старой схемой. Чтобы перейти на каталог, добавьте поле «Комнаты» через свойства формы и настройте светильники. После сохранения списка комнат шлюз обслуживает часы через `/v2`. Установите на часы версию с поддержкой каталога. Шлюз не создаёт правил и виртуальных устройств. [Редактор Wiren Board](https://wiki.wirenboard.com/wiki/Usage-Guide-JSON-Editor) · [Меню HomeUI](https://github.com/wirenboard/homeui#custom-menu)

Если после обновления веб-интерфейс показывает ошибку `MQTT RPC request timed out` при открытии конфигурации, перезапустите редактор командой `sudo systemctl restart wb-mqtt-confed` и обновите страницу.

Шлюз слушает `127.0.0.1:8765` и использует брокер на `127.0.0.1:1883`. Для каталога требуется серийный номер из `/var/lib/wirenboard/short_sn.conf`, совпадающий с `/devices/system/controls/Short SN` в MQTT. Если схема недоступна, проверьте `journalctl -u wb-wear-light-gateway`. Контроллер должен публиковать метаданные выбранных каналов в `/meta` — `switch`, `range` с максимумом 100, `rgb` или `pushbutton` согласно назначению. [Соглашения Wiren Board по MQTT](https://github.com/wirenboard/conventions/blob/main/README.md)

После настройки внешнего HTTPS-адреса можно открыть окно привязки через терминал контроллера. Если служба включена, выполните команды от имени администратора.

```sh
sudo systemctl kill --kill-who=main --signal=SIGUSR1 wb-wear-light-gateway
sudo cat /run/wb-wear-light-gateway/pair-code
```

Для WB Cloud введите восьмизначный код в установщике на компьютере. При использовании собственного HTTPS-адреса код вводится в разделе «Настройки → Подключение → Вручную → Свой HTTPS» на часах. Он действует пять минут и погашается после первого использования. Ключ хранится с правами `0600` в `/var/lib/wb-wear-light-gateway/token.env`. Чтобы отозвать доступ потерянных часов, остановите службу, удалите этот файл и выполните `sudo dpkg-reconfigure wb-wear-light-gateway`. Пакет создаст новый ключ. Если шлюз включён в настройках, запустите службу командой `sudo systemctl start wb-wear-light-gateway` и привяжите часы повторно.

## Привязка через Wiren Board Cloud

1. Включите шлюз в веб-интерфейсе контроллера. В личном кабинете WB Cloud откройте этот контроллер → **Сервисы** и добавьте порт `8765`. Имя в списке можно выбрать своё.
2. Распакуйте архив для Windows с приложением и программой привязки. Подключите часы к компьютеру через Android Debug Bridge (ADB) и запустите `install_wb_cloud.cmd`. Вам понадобятся Python 3 и Android Platform Tools. Один раз войдите в WB Cloud на компьютере. Выберите аккаунт, которому можно доверить доступ с этих часов. Код двухфакторной защиты нужен, если она включена.
3. Программа подключится к опубликованному сервису и привяжет пульт по одноразовому коду шлюза. Когда сами часы прочитают состояние света, установщик это подтвердит. Открывать сайт на часах не требуется.

По умолчанию установщик обращается к приложению `com.galaxywatch.home.sample`. Если в своей копии изменили `applicationId`, укажите его также в `PACKAGE` в [install_wb_cloud.py](../tools/install_wb_cloud.py).

Если часы будут доступны позже, откройте [форму предварительной привязки](../tools/prepare_wb_cloud.cmd). Для запуска той же формы из терминала Windows выполните команду.

```powershell
python tools/install_wb_cloud.py --prepare
```

Установщик сначала прочитает состояние через облако и сохранит профиль в зашифрованном хранилище текущего пользователя Windows. Пароль в файл не записывается. Когда часы будут рядом, запустите `tools/install_wb_cloud.cmd` из той же учётной записи на этом ПК. Скрипт найдёт подготовленный профиль и удалит его с компьютера после того, как часы подтвердят чтение. Если часы уже сопрягались по ADB, но не подключились автоматически, укажите IP и порт с основного экрана «Беспроводная отладка». Для первого сопряжения используйте `adb pair` с данными, которые показывают часы. [Беспроводное подключение ADB](https://developer.android.com/tools/adb#wireless-android11-command-line)

При наличии уже открытого администратором сеанса PuTTY к контроллеру параметр `--pair-with-putty IP_КОНТРОЛЛЕРА` позволяет получить краткоживущий код автоматически. Привязка через ADB рассчитана на входящий в проект отладочный APK. Для отзыва доступа облачную сессию можно завершить в настройках безопасности WB Cloud.

При первичной привязке установщик дожидается чтения через WB Cloud даже дома. После этого при наличии локального адреса часы одновременно проверяют оба подключения и используют первое, которое подтвердило состояния дома. Вручную закрепить один канал можно в меню «Настройки → Подключение».

Выключатель в интеграциях WB останавливает шлюз, закрывает порт и отзывает опубликованный каталог. Локальный режим подключается прямо к MQTT. Для управления по каталогу часы сверяют серийный номер контроллера и ревизию схемы.

## Сборка пакета из исходников

На компьютере с Debian 11 или новее выполните команды из корня репозитория. Готовый файл `wb-wear-light-gateway_0.2.0_all.deb` появится рядом с каталогом `remote`.

```sh
sudo apt install build-essential debhelper dpkg-dev
cd remote
chmod 0644 debian/*
chmod 0755 debian/rules debian/postinst debian/postrm
dpkg-buildpackage -b -us -uc
cd ..
```

## Локальный запуск

1. Установите Python 3.9 или новее и зависимости командой `python -m pip install -r remote/requirements.txt`.
2. Создайте случайный токен командой `python -c "import secrets; print(secrets.token_urlsafe(32))"`. Сохраните его в менеджере паролей и передайте шлюзу в переменной окружения `WB_GATEWAY_TOKEN`.
3. Для отдельного стенда задайте адрес брокера в `WB_MQTT_HOST` и при необходимости порт в `WB_MQTT_PORT` (по умолчанию `1883`). Если требуется вход в брокер, задайте `WB_MQTT_USERNAME` и `WB_MQTT_PASSWORD`. [Настройка доступа к MQTT в Wiren Board](https://wiki.wirenboard.com/wiki/MQTT)
4. Запустите `python remote/gateway.py --switch-config ПУТЬ_К_КОНФИГУРАЦИИ`. Порт HTTP выбирается аргументом `--port`. Запуск без файла использует учебную карту `/v1`.
5. Получите каталог через локальный запрос PowerShell.

   ```powershell
   Invoke-RestMethod http://127.0.0.1:8765/v2/layout -Headers @{ Authorization = "Bearer $env:WB_GATEWAY_TOKEN" }
   ```

Для внешнего адреса используйте действительный TLS-сертификат. Направляйте туннель только в этот шлюз. Используйте MQTT через loopback или в доверенной домашней сети.

## Подключение часов

1. Для запуска вручную добавьте `--pair-once`, сохранив настроенный `WB_GATEWAY_TOKEN` и аргумент файла конфигурации. Если порт уже занят работающим шлюзом, сначала остановите его.
2. На часах откройте «Настройки → Подключение → Вручную → Свой HTTPS», введите внешний `https://` адрес и напечатанный в терминале восьмизначный код, включая ведущие нули. Код действует пять минут. После использования или восьми неверных попыток выдача закрывается до нового запуска с `--pair-once`.
3. После подключения шлюз продолжает обслуживать часы. При обычном запуске выпуск нового кода выключен. При потере часов замените токен в окружении шлюза, перезапустите его с `--pair-once` и повторите привязку.

`POST /v1/pair` принимает `{"code":"01234567"}` без заголовка `Authorization` и один раз возвращает токен. `400` означает неверный формат, `403` — неверный код, `429` — лимит ошибок, `410` — выдача недоступна. Остальные запросы требуют `Authorization: Bearer …`.

## Запросы приложения

Каталог и его ревизия публикуются в сохраняемых MQTT-сообщениях `/devices/wb-wear-light-gateway/controls/Catalog` и `/devices/wb-wear-light-gateway/controls/CatalogRevision`. По HTTPS доступны три запроса.

- `GET /v2/layout` возвращает схему версии `1`, серийный номер контроллера, ревизию, комнаты, светильники и выбранные каналы. Ревизия — SHA-256 от JSON в UTF-8 со всеми полями схемы, кроме самой ревизии. Ключи объектов отсортированы, порядок элементов списков сохранён.
- `GET /v2/state` возвращает `revision`, `vacation` и `lights`. Для светильника приходит `power` и только настроенные `brightness` и `color`. `null` обозначает неизвестное состояние. Без выбранного канала «Отпуск» поле `vacation` равно `false`.
- `POST /v2/command` принимает актуальную `revision` и `changes`, например `{"changes":{"lamp":{"brightness":35}},"revision":"…"}`. Можно изменить по одному параметру каждого светильника. Допустимы `power` (`true` или `false`), `brightness` (целое `0…100`) и `color` (например, `"0;128;255"`). Для общего выключения передайте `{"allOff":true,"revision":"…"}`. Успешный ответ содержит подтверждённое состояние.

`403` означает, что «Отпуск» включён или его состояние неизвестно. `409` означает, что схема изменилась или шлюз выполняет другую команду. `503` означает, что шлюз ещё не подтвердил брокер, серийный номер или выбранные каналы. `504` означает отсутствие подтверждения, при этом команда могла успеть изменить свет. Команды не повторяются автоматически.

Для старого файла настроек со строкой `enabled` и без списка комнат доступны запросы прежних часов.

- `GET /v1/state` возвращает состояние «Отпуска» и всех 12 каналов. Значение `null` означает, что состояние ещё неизвестно.
- `POST /v1/lights` принимает `{"lights":{"101/K1":false}}` либо `{"allOff":true}`. Отдельная команда для `102/K4` запрещена. В общее выключение входят все 12 каналов.
- Успешная команда возвращает такой же снимок, как `GET`. Шлюз ждёт свежие значения изменяемых линий, затем сверяет все целевые состояния. Общее выключение отправляет существующую команду `AllOff` один раз. Если все 12 линий уже выключены, снимок показывает состояние света, а отправка MQTT подтверждает запись команды в сокет.
- `401` означает неверный токен, `403` — включённый или неизвестный «Отпуск», `409` — уже выполняется команда. `503` означает, что брокер недоступен. При `504` приложение не получило подтверждения, часть линий могла успеть изменить состояние. Шлюз не повторяет команды.

Проверка с имитацией MQTT и локальными HTTP-запросами запускается так.

```powershell
python -B -m unittest discover -s remote -v
```
